# 电信客户流失教学数据

本数据集随项目固定交付，不需要运行生成脚本。客户编号为项目内部标识，业务表覆盖 2024-10-01 至 2026-01-31；完整性水位右开边界为 2026-02-01。

| 表 | 行数 |
|---|---:|
| customers | 200,000 |
| usage | 79,588,503 |
| invoices | 2,655,420 |
| tickets | 469,781 |
| events | 90,402 |

五张表合计 83,004,106 行，压缩文件合计 751.6 MiB。按客户划分为 20 个 `part-000` 至 `part-019` 目录，每片 10,000 名客户，五张表采用相同客户分区。单个客户的完整历史保留在同一片内。每个目录包含 `customers.csv.gz`、`usage.csv.gz`、`invoices.csv.gz`、`tickets.csv.gz`、`events.csv.gz`。

## 使用方式

在项目根目录执行：

```bash
uv run --frozen --extra lightgbm churn build-features --raw-dir data/bundled --data-end 2026-02-01
```

程序逐分片读取、校验和聚合，再合并月度特征。不要将同一客户放到多个分片。普通的未分片 CSV 目录仍可读取。

详细字段见 `docs/data-contract.md`，操作顺序见 `docs/tutorial.md`。小规模练习和测试使用独立的 `tests/data/`，不需要扫描全量明细。

## 来源与使用范围

数据为一次性按规则合成的固定教学数据，随机种子为 42，不包含运营商真实客户。合约、流量、投诉与流失之间的关系由构造规则设定；不能用其评估结果证明真实业务预测能力或挽留收益。来源标识保留在 `metadata.json`，并随特征和模型版本传递。源项目不保留数据生成代码。

根目录 `metadata.json` 记录每个压缩文件的字节数和 SHA-256，可检查传输是否完整。此数据用于单机百万级明细处理与机器学习工程练习，不代表已完成真实运营商数据治理或分布式生产部署。
